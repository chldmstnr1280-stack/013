# 단계별 구현 결과와 테스트 방법

공통 준비: `npm install && npm run dev` (APP_MODE=mock). 자동 테스트: `npm test` (23개), `npm run lint`, `npm run build`.

## 1단계 — 프로젝트 구조 및 DB 설계
- 결과: `docs/ARCHITECTURE.md`, `supabase/migrations/0001_init.sql`, `Store` 추상화(mock/live 동일 인터페이스), 모의 seed 데이터
- 테스트: Supabase SQL Editor 에서 마이그레이션 실행 → 테이블 11개·RLS 확인. `tests/mock-store.test.ts` 가 고유 제약/조건부 갱신을 검증

## 2단계 — 상품 관리
- 결과: 상품 등록/수정/삭제, 가격 미확인(null) 허용, 이미지 사용 권한, 정보 확인일, (키가 있을 때) 쿠팡 딥링크 생성
- 테스트: **상품 관리 → + 상품 등록** → 저장 후 목록 배지(제휴 링크/이미지 권한) 확인. 잘못된 URL·음수 가격 입력 시 오류 메시지

## 3단계 — Claude 콘텐츠 생성
- 결과: 5개 유형 중 3개를 골라 서로 다른 관점의 초안 생성, 기존 게시물 말투 참고, 본문에 광고 표시 자동 추가, 링크·수수료 안내는 답글로 분리. 구조화 출력(Zod)으로 응답 검증, 거절/길이 초과/인증/한도 오류 처리 및 `api_logs` 기록
- 테스트(mock): **AI 콘텐츠 생성** → 초안 3개 생성 → `[모의 생성]` + 모의 배지 확인
- 테스트(live): `ANTHROPIC_API_KEY` 설정 후 같은 절차. 발행 기록 화면 하단 "최근 API 기록"에 토큰 사용량 기록

## 4단계 — 검토 및 승인
- 결과: 본문/답글/이미지 수정(500자 카운터), 자동 검수 6항목(정확성·중복·과장·광고 표시·이미지 권한·링크), 사람 확인 체크 6개, 승인 게이트, 반려/삭제
- 테스트: 초안 본문에 `한 달째 써보니 30% 할인, 무조건 최고` 입력 → 저장 → 정확성/과장 '수정 필요' 표시, 승인 불가 확인. 문구 제거 후 6개 체크 → 승인

## 5단계 — Threads 연결 및 테스트 발행
- 결과: OAuth(state 검증) → 장기 토큰 암호화 저장 → 자동 갱신. 컨테이너 생성 → 상태 확인 → publish → permalink 저장 → 제휴 링크 답글
- 테스트(mock): 승인된 콘텐츠의 **테스트 발행 (모의)** → 발행 기록에 '발행 완료' + 답글 '작성됨'
- 테스트(live): `docs/SETUP.md` 3절 설정 → 설정 화면에서 계정 연결 → 테스터 계정으로 **지금 발행 (테스트)** → 발행 기록의 "Threads 에서 보기" 링크 확인

## 6단계 — 예약 발행
- 결과: 다음 빈 슬롯 자동 배정/지정 시간 예약, 하루 최대 3개(설정 1~3), 시간대 처리, 변경/취소, 일시 정지/재개, 지수 백오프 재시도(5→10→20분, 최대 3회), 최종 실패 알림(앱 + webhook), 중복 발행 4중 방지
- 테스트: 예약 캘린더에서 같은 날 4번째 예약 시도 → 한도 오류. 본문에 `[실패테스트]` 를 넣어 승인·테스트 발행 → '재시도 예정' 표시 → 3회 후 실패 + 대시보드 알림. 일시 정지 후 '예약 처리 지금 실행' → "건너뜀: 자동 발행 일시 정지 중"
- Cron 직접 호출: `curl -H "Authorization: Bearer $CRON_SECRET" http://localhost:3000/api/cron/publish`

## 7단계 — 성과 분석
- 결과: Threads 인사이트(조회·좋아요·답글·리포스트·인용) 수집, 쿠팡 실적 CSV 업로드(한글/영문 헤더, 추적코드·상품명 매칭, 빈 칸=측정 안 됨), 상품별/유형별/게시물별 집계, 데이터 출처 배지, 가져오기 묶음 삭제
- 테스트: **수익 분석 → CSV 템플릿 내려받기** → `sub_id` 에 콘텐츠 추적코드 입력 후 업로드 → 해당 게시물 행에 클릭/구매/수수료 표시, 비어 있는 값은 `—`

## 8단계 — 배포 및 운영 테스트
1. GitHub 저장소를 Vercel 에 Import → 환경 변수 입력(`APP_MODE=live` 포함)
2. Threads 앱 리디렉션 URL 을 배포 도메인으로 등록, `THREADS_REDIRECT_URI` 일치 확인
3. 배포 후: 로그인 → 계정 연결 → 상품 1개 → 생성 → 승인 → 10분 뒤로 예약 → Cron 실행 후 발행/답글 확인
4. 운영 점검: 대시보드 알림, 발행 기록의 API 로그, Supabase `api_logs` 테이블
5. Hobby 플랜이면 외부 스케줄러로 Cron 호출 (SETUP.md 4절)
